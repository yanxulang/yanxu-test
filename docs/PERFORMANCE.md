# 性能

## 资源预算

- 深复制与深比较默认最大深度 64、最大节点 100000；
- 套件最多 4096 个测试、256 个夹具和每类 256 个钩子；
- 名称最多 256 字符；
- 仓储初始记录与更新变化各最多 256 个字段。

这些预算用于拒绝明显失控输入，不是吞吐承诺。调用方可用受限 API 设置更小的单次比较预算。

## 基准

`benchmarks/核心性能.yx`分别测量深比较、深复制和 Mock 调用记录，并用校验和防止空跑：

```sh
yanbao run --manifest-path benchmarks -- 1000
```

轮数范围为 1 至 10000。输出包含轮数、三段耗时和校验和。不同操作系统、构建模式和机器的绝对数值不可直接比较；回归判断应在固定工具链、同一机器和多次采样下进行。

## 使用建议

- 大量同构案例优先用表格测试，避免建立数千个套件对象；
- Mock 调用记录与 HTTP 请求记录随调用数线性增长，压力测试后及时丢弃实例；
- 快照库每次更新写出完整 JSON 典，不适合超大二进制样本；
- 仓储契约面向功能一致性，不替代数据库吞吐基准。
