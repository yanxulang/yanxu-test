# 使用指南

## 组织测试

小型纯函数可直接使用断言。涉及多个资源时使用套件，把创建逻辑放入夹具，把恢复逻辑放入清理法。夹具只在测试实际请求时创建，因此未使用资源没有清理负担。

需要自定义报告器时调用`尝试运行()`；命令行规格通常调用`运行()`，让失败转换成非零退出。

## 数据驱动

表格行应包含可读名称和输入/期望字段。参数化测试适合位置参数组合；复杂案例优先使用行典，失败报告会保留行名。

不要在一个表格中放入无界数据。深比较和复制有默认预算，较大合法样本应显式调用受限 API 并记录理由。

## 隔离资源

临时目录的基础路径应由顶层测试项目专用，测试结束后调用`清理()`。子路径不能包含`..`或反斜线。环境隔离是内存视图，不会替你恢复真实进程环境，因为它从不修改真实环境。

快照更新应是显式操作。评审快照文件变化，避免把凭据、Cookie、个人信息或大正文写入仓库。

## 数据库测试

```yanxu

    事务.执行（「INSERT INTO users(name) VALUES (?)」，【「子衿」】）；
    归 1；
```

连接必须支持言库托管事务。回调可以返回值，但不能自行提交；测试完成后连接会回滚并恢复可用状态。

## 仓储契约

仓储契约适合让 SQLite、PostgreSQL、MySQL 和测试替身共享同一 CRUD 语义。为每个后端创建隔离数据库或事务，再实现`重置()`。契约会清空仓储两次，因此不应复用开发或生产数据源。

## 并发

套件对象、Mock、Spy、快照库、HTTP Mock 和函数仓储适配器都持有可变状态，不应跨并发测试共享。为每个测试创建独立实例，测试运行器使用共享依赖缓存时可设置`--并发 1`。
