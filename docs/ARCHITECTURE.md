# 架构

## 模块边界

言试保持单一公开入口`src/言试.yx`，便于消费者只导入`包:言试`。内部能力分为五层：

1. 错误解析、深复制和资源预算；
2. 断言与数据驱动；
3. 套件、夹具、临时目录和环境视图；
4. Mock、Spy、快照和 HTTP 传输；
5. 言库事务与仓储契约集成。

依赖方向只从通用层流向集成层。言试不实现 HTTP 客户端或数据库协议，而是分别复用言访自定义传输与言库完成后回滚事务。

## 状态所有权

所有可变状态都属于显式对象：套件拥有注册表，测试上下文拥有夹具实例，Mock/Spy 拥有调用记录，快照库拥有文件内值，HTTP Mock 拥有路由与请求，仓储由调用方拥有。

没有全局 Mock 注册表、全局网络替换或隐式数据库事务。模块级临时序号只用于避免同一进程内名称碰撞，不承载业务状态。

## 生命周期

套件先执行全部前置钩子。前置失败会让测试标记跳过，但仍运行全部后置钩子。每项测试按前置、测试体、全部后置、逆序夹具清理执行，并收集所有可确定错误。

夹具在调用清理法前先清除内部已创建状态，防止失败清理被重复执行。数据库测试事务把状态机交给言库；仓储契约在主操作之外单独执行最终重置，并在主错误存在时保留主错误。

## 错误边界

言试自产错误统一为`YANSHI_TEST_*`。言访、言库、文件系统、正则和调用方回调的错误通常原样传播，避免把底层原因伪装成断言失败。只有适配器返回形状、契约断言和清理失败会转换为对应言试代码。

## 生成接口

`docs/API_REFERENCE.md`由`yanxu 文`从公开声明生成。CI 同时生成 JSON 机器清单，检查格式版本、模块名、声明数量和关键成员，再重新生成 Markdown 与已提交文件比较。
